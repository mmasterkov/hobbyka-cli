# Hobbyka CLI

Работать с Hobbyka только через `scripts/hobbyka-cli.mjs`. Не обращаться к API или MCP напрямую и не придумывать цены, скидки либо характеристики.

1. Сохранить исходный запрос пользователя и выполнить его без контактов: `node scripts/hobbyka-cli.mjs search --query "..." --limit 10`. Не менять смысл, фильтры, количество и бюджет ради авторизации.
2. Полностью собрать публичный ответ: разрешены дополнительные `search` с уточнённой формулировкой в пределах исходных требований и `product` для чтения карточек. Пустой или слишком узкий первый поиск не является поводом начинать вход.
3. Сначала показать готовую подборку, публичные цены и ссылки. Завершить публичный ответ отдельным абзацем с точным текстом: «Для того чтобы увидеть партнерские цены и получить доступ к созданию КП необходимо авторизоваться, хотите это сделать?». Не сокращать, не перефразировать и не добавлять этот вопрос в предыдущий абзац.
4. Если пользователь уже зарегистрирован на сайте и согласился войти, пройти сценарий из раздела «Вход через Codex».
5. После успешного входа использовать `replayed_request`, который CLI формирует из сохранённой исходной команды. Если публичный ответ собирался несколькими командами, повторить оставшиеся команды с теми же аргументами. Для каждого изменившегося значения явно сопоставить данные до и после входа; если данные совпали, прямо сообщить об отсутствии изменений.
6. Если аккаунта сайта нет, предложить регистрацию на сайте либо сохранение контакта. Объяснить: «Сохранить контакт — записать имя, телефон или email и интерес клиента. Эти данные нужны менеджеру для продолжения работы и связи с клиентом, но не открывают автоматическое создание КП». После согласия передать контакт CLI через стандартный ввод: `node scripts/hobbyka-cli.mjs contacts set --stdin`. Не помещать контакт в аргументы процесса, журналы или итоговый ответ.
7. Считать изображения из поля `images` частью данных для визуального сравнения.
8. Создавать КП только после входа через сайт. Подтвердить идентификаторы и количества, затем выполнить `node scripts/hobbyka-cli.mjs offer create --items "123:2,456:1"`.

Публичные `search` и `product` доступны для полного выполнения первого пользовательского запроса. Создание КП требует входа через существующий аккаунт Hobbyka. Контактный шлюз использовать только для передачи запроса менеджеру пользователем без аккаунта сайта и только после согласия.

## Вход через Codex

1. Выполнить `node scripts/hobbyka-cli.mjs auth login`.
2. При статусе `already_authorized` использовать возвращённый профиль и сразу повторить исходный запрос.
3. При статусе `site_authorization_required` открыть `verification_uri_complete` во встроенном браузере Codex, если он доступен, и сделать страницу видимой пользователю. При отсутствии встроенного браузера показать кликабельную ссылку.
4. Пользователь самостоятельно входит в обычный кабинет Hobbyka и подтверждает показанные на странице пользователя и организацию. Логин, пароль, код подтверждения и токен в чате не запрашивать и не выводить.
5. После подтверждения выполнить `node scripts/hobbyka-cli.mjs auth complete`. Статус `authorization_pending` означает, что следует дождаться подтверждения на открытой странице. После `authorized` проверить `auth status`.
6. Проверить `access.mode`: `partner` включает партнёрский режим, `admin` включает административный режим. Сравнить `replayed_request` с публичным ответом до входа.

Команда `auth login` для уже подтверждённого профиля безопасно вернёт `already_authorized`. Для смены пользователя требуется явный `auth logout` после подтверждения владельца. Команды `partner login|complete|status|logout` сохранены как совместимые псевдонимы.

Режим назначает сервер Hobbyka по учётной записи. Не передавать и не предлагать пользователю локальный выбор режима.

## Партнёрский режим

В партнёрском режиме использовать те же `search` и `product`: сервер вернёт цены и условия связанного пользователя сайта. Для полного цикла доступны:

- `offer create`, `offer list`, `offer status`, `offer revise`, `offer archive`;
- `order create`, `order list`, `order get`, `order update`, `order cancel`.

Перед изменением получить текущую карточку и передать её `version` как `--expected-version`. При `version_conflict` повторно прочитать объект и согласовать изменение. Цены, скидки и итоги никогда не передавать со стороны CLI.

## Административный режим

Если `access.mode` равен `admin`, сообщить, что пользователь вошёл как менеджер или администратор Hobbyka. Использовать только возможности, перечисленные сервером в `capabilities`.

- Все КП: `admin offers list` и `admin offers get --id <id>`.
- Все заказы: `admin orders list` и `admin orders get --id <id>`.

Сначала применять узкие фильтры по периоду, номеру, менеджеру, пользователю или статусу. Для деталей запрашивать одну карточку по ID. Отсутствие capability означает, что функция пока недоступна.

Параметр `--recommendation-profile <id>` зарезервирован для будущих служебных рекомендаций Hobbyka. Он не должен заменять или ослаблять явные требования пользователя.

Официальная точка обнаружения, документация и рабочий API находятся на `https://hobbyka.ru`. Этот адрес уже задан в CLI. `HOBBYKA_BASE_URL` использовать только для изолированных локальных или тестовых проверок после подтверждения работоспособности выбранной среды.
